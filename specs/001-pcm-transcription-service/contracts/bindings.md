# Contract: C and Python bindings

Both are thin. They add no behaviour of their own; everything they promise is
[rust-core-api.md](./rust-core-api.md) restated in a way each language can hold.

## C API

`capi/include/edge_stt.h` is generated by cbindgen from the Rust source and committed; a test
regenerates it and fails when the two have drifted. Nothing in it is written by hand.

The documentation is generated the same way. Every entry point carries `@brief`, `@param`,
`@return`, and `@see` in its Rust doc comment, `cbindgen.toml` sets `documentation_style =
"doxy"` so those cross into the header, and `capi/Doxyfile` reads the header alone — the same
chain edge-ear uses, so the two libraries' C documentation looks like one set.

The conventions are edge-ear's, not new ones: an opaque handle typedef, a constructor returning
the handle or `NULL`, `int32_t` from anything that can fail, and a thread-local message behind
the last failure.

```c
edge_stt_h *stt = edge_stt_new();
if (!stt) { fprintf(stderr, "%s\n", edge_stt_last_error()); return 1; }

if (edge_stt_load_model(stt, "models/ggml-base-q5_0.bin") != 0) {
    fprintf(stderr, "%s\n", edge_stt_last_error());
    edge_stt_free(stt);
    return 1;
}

edge_stt_transcript *out = NULL;
if (edge_stt_transcribe(stt, samples, n_samples, 16000, &out) == 0) {
    printf("%s\n", edge_stt_transcript_text(out));
    edge_stt_transcript_free(out);
}

edge_stt_free(stt);
```

**Rules**

- The prefix is `edge_stt_` and nothing repeats it. `edge_stt_new`, not
  `edge_stt_transcriber_new` — the handle's identity is already in the prefix, which is why
  edge-ear says `edge_ear_new`.
- `edge_stt_new` returns the handle or `NULL`; everything else that can fail returns `int32_t`,
  zero on success. `edge_stt_last_error()` gives the message behind the last failing call on
  this thread, borrowed until the next one fails.
- The message carries the detail the Rust error variant carried — the format expected against
  the one received, the path that was searched — so a C caller loses nothing to the boundary.
- Zero is success and each error variant has its own negative code, so `at capacity` and `bad
  credential` are distinguishable without parsing English. This is edge-ear's convention, kept
  rather than improved on.
- Every `_new` has a matching `_free`, and `_free` on `NULL` is a no-op.
- Strings handed out are owned by the object they came from and die with it.
- Partials arrive through `edge_stt_on_partial(stt, callback, user_data)`, called on the thread
  that called `edge_stt_transcribe`, never after it has returned. The name mirrors
  `edge_ear_on_event`.
- Cancellation is `edge_stt_cancel(stt)`, callable from another thread.
- No panic crosses the boundary. Every entry point catches unwinding and turns it into a code.

## Python

`py/`, built with maturin and pyo3 against abi3-py39, the same as edge-ear.

```python
from edge_stt import EdgeStt

with EdgeStt(model="models/ggml-base-q5_0.bin") as t:
    result = t.transcribe(samples, sample_rate=16000)
    print(result.text)

    for partial in t.transcribe_stream(samples, sample_rate=16000):
        print(partial.text, end="", flush=True)
```

**Rules**

- `transcribe` returns a `Transcript` object whose attributes are the fields in
  [data-model.md](../data-model.md), converted to Python types — `Duration` becomes seconds as a
  float, `Language` becomes a string.
- `transcribe_stream` is a generator yielding partials and is the Pythonic face of the callback.
  The final transcript is available on the generator once it is exhausted.
- Each error variant maps to its own exception class under a common `EdgeSttError` base, so
  `except NetworkError` is possible without inspecting a message string.
- The GIL is released around decoding, so a Python program can do something else meanwhile.
- `samples` accepts anything supporting the buffer protocol — `bytes`, `bytearray`, and a numpy
  `int16` array — without a copy where the layout already matches.
